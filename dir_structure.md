## Where's What

There are more directories than this, but intead of listing them all,
here are the ones I usually care about:
* `config`
  * config.exs
  * runtime.exs
  * dev.exs
  * prod.exs
* `lib` - source code
  * lib/<app_name>
* `priv` - DB scripts

## Source code - core logic (not web)
These core logic modules are under `./lib/<app_name>`

Key files:
* application.ex
* repo.ex
* mailer.ex - swoosh email delivery


## Web Stuff
All the web stuff is under ./lib/<app_name>_web

```
./lib/<app_name>_web/endpoint.ex
(plug handling, last goes to router)
        |
        v
./lib/<app_name>_web/router.ex
(dispatches to controller)
        |
        v
./lib/<app_name>_web/controllers
        |
        v
View Module to render HTML pages
./lib/<app_name>_web/controllers/<appname>HTML.ex
ex: ./lib/hello_web/controllers/HelloHTML.ex
```

## What is a Route?
Route maps a tuple {HTTPverb, path} to {Controller, Action}
where HTTPverb = "GET"|"POST" and path looks like a filesystem path,
and Action is a function.
Edit router.ex to add new routes.

## Steps
### Endpoint
./lib/<app_name>_web/endpoint.ex

Probably don't need to edit this,
many plugs handle each incoming request,
the last plug is the router.

### Edit Router
./lib/<app_name>_web/router.ex

```{code-block} elixir
:linenos: true
:emphasize-lines: 5
  scope "/", HelloWeb do
    pipe_through :browser

    get "/", PageController, :home
    get "/hello", HelloController, :index
  end
```
In line 5 we add the new route. "get" is the HTTPverb here, and the path is "/hello".
This maps to the controller `HelloController` and the action `index/2`

### Make a Controller
Using the controller name and action from the router step, create the new Controller.

```elixir
defmodule HelloWeb.HelloController do
  use HelloWeb, :controller

  def index(conn, _params) do
    render(conn, :index)
  end
end
```
`index/2` above is the function for the action.
`conn` has information about the request.
`params` has information about the request parameters (i.e., in the URL)

### Make a View
./lib/<app_name>_web/components/<app_name>HTML.ex

defines `index/1`.
can use ~H which is HEEx (HTML + EEx).
EEx is Embedded Elixir.

Example:
```elixir
defmodule HelloWeb.HelloHTML do
  use HelloWeb, :html

  def index(assigns) do
    ~H"""
    Hello!
    """
  end
end
```

## Using Templates

Instead of using an action function as we did in {ref}`make_view`,
we can use a HEEx template.

Edit 
./lib/<app_name>_web/components/<app_name>HTML.ex

```{code-block} elixir
:linenos: true
:emphasize-lines: 4
defmodule HelloWeb.HelloHTML do
  use HelloWeb, :html

  embed_templates "hello_html/*"
end
```
As seen in line 4, use the `embed_templates` directive instead. It will make
functions for all the templates in the parameter we passed in (`hello_html`).

### HEEx template
The filenames in the embed directory follow the naming convention
NAME.FORMAT.TEMPLATING_LANGUAGE.
Following this, our first file will be `index.html.heex`.

```html
<section>
	<h2>Hello world!</h2>
</section>
```

## Passing parameter

### New route
`get "/hello/:messenger", HelloController, :show`
We're still using the /hello path but now we capture the next
path element into `:messenger`

We will send this over to the same controller but with the
`show/2` action


### New action
```{code-block} elixir
  def show(conn, params) do
    render(conn, :show, messenger: Map.get(params, "messenger"))
  end
```

Notice we get a params as a map and in there we have "messenger"
which was defined in the router.

Render is calling `show/1` which will be definted by the template.
 
### New template
Note the filename which autogenerated the show function: show.html.heex

We can use the "messenger" paramter as `@messenger`:
```
<Layouts.app flash={@flash}>
  <section>
    <h2>hello world from {@messenger}!</h2>
  </section>
</Layouts.app>
```
